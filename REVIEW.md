# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Always returns 200, never pings MongoDB. Contract requires 200 only when Mongo answers, else 503. | Stop Mongo, `GET /health` still 200. | `client.admin.command("ping")`, 503 on failure. |
| 2 | `compute_late_minutes` | Uses naive `punch_in.replace(hour…)` (server-local, not IST), no truncation, grace test `minutes > 10` on floored minutes. `09:40:01` (shift 09:30) floors to 10 → returns 0, must be 10. | Punch at `09:40:01 IST` → `late_minutes 0`, expect 10. | IST-aware diff, `diff <= 600 → 0` else `floor(diff/60)`, inputs pre-truncated to seconds. |
| 3 | `compute_work_hours` | `round()` is banker's rounding, not half-up. | A duration of exactly `2.345h` rounds to `2.34`, must be `2.35`. | `Decimal(...).quantize(0.01, ROUND_HALF_UP)`. |
| 4 | `compute_overtime` | No 30-min minimum (`max(0,…)`), no overnight handling (`shift_end` always on `date`), naive `fromisoformat` + `tzinfo=IST` mix. | Punch-out 29 min after end → 29, must be 0. Overnight `22:00-06:00` overtime from wrong day. | Floor minutes, `>=30` else 0; `shift_end` on next day when `shift_end <= shift_start`. |
| 5 | `EmployeeIn` | No validation: `emp_code` pattern, `email` pattern, `shift HH:MM` pattern, `joined_on` date, `shift_start != shift_end`. | `POST /employees {"emp_code":"BAD"}` → 201, must be 422. Equal shifts → 201, must be 422. | Pydantic `pattern`/`min_length` + explicit `shift_start == shift_end → 422`. |
| 6 | `PunchInIn` | `status: str` accepts anything; `punched_at: Optional[int]` coerces floats/strings and accepts seconds-looking values. | `{"status":"ABSENT"}` → 201, must be 422. `punched_at: 1753000000` or `1.5` or `"123"` → 201, must be 422. | `Literal[PRESENT,WFH,ON_DUTY]`, `Annotated[int, Field(strict=True, ge=1e11, le=4102444800000)]`. |
| 7 | `create_employee` | Check-then-insert race (`find_one` + `insert`), no unique index, no `DuplicateKey` catch; `created_at=datetime.now()` naive local; returns datetime (ISO string) not epoch ms. | 10 parallel duplicate creates → >1×201. `created_at` is `"2026-…"` string, must be int ms. | Unique `emp_code` index + `try/insert except DuplicateKey → 409`; UTC-now truncated to seconds; serialize to millis. |
| 8 | `list_employees` | `skip = page*page_size` (skips page 1 entirely); `total=count({})` ignores filter; no `sort`; no `page/page_size` bounds; `created_at` not converted. | `GET /employees?page=1` misses first 20. `?department=X` total is whole collection. `?page=0`/`page_size=101` → 200, must be 422. | `(page-1)*size`, `count(q)`, `sort emp_code`, `Query(ge/le)`, millis conversion. |
| 9 | `punch_in` | No 404 (`emp["shift_start"]` → 500 TypeError on unknown emp); `fromtimestamp()` naive local, `ts.date()` server-local (not IST, no overnight R1, no truncation); check-then-insert race; no validation; returns datetimes + extra `"id"` field. | Unknown `emp_code` → 500, must be 404. IST `00:30` punch gets wrong `date` on US server. Parallel same-date punch-ins → duplicates. Response has `"id"`, punch times are ISO strings. | 404 guard; truncate ms → aware UTC → IST date via R1 (overnight shift-back); unique `(emp_code,date)` + catch 409; strict validation; serialize millis, no `id`. |
| 10 | `list_attendance` | Loads whole collection + Python `sort/slice` (dies at 100k); sorts by `date` only (missing `emp_code` tiebreak); adds `"id"`, returns datetimes; no `date_from>date_to → 422`, no pagination bounds. | 100k docs → seconds + OOM. Same-date rows in random `emp_code` order. `?date_from=07-10&date_to=07-01` → 200, must be 422. | DB `find().sort(date -1, emp_code 1).skip().limit()`, `count_documents(q)`, 422 checks, millis + defaults (`half_day False`, `history []`). |
| 11 | Startup / indexes | No index creation at all; seeded DB has only `_id`. All list/analytics queries COLLSCAN at scale; uniqueness races unfixable without indexes. | `explain` shows `COLLSCAN`; duplicate races pass. | `ensure_indexes()` at import + `startup` event, idempotent: unique `emp_code`, unique `(emp_code,date)`, `(date,emp_code)`, `date`, `status`, `(emp_code,punch_in)`, `department`, `joined_on`. |
| 12 | Time / truncation | Everywhere naive datetimes treated as local; R1 truncation ("09:40:00.900 counts as 09:40:00") never applied; IST only defined, never used for dates. | Punch `09:40:00.900` stored with ms and late computed from untruncated value. | `tz_aware=True` client, naive→UTC assumption, `ms//1000*1000` everywhere, IST conversions for date/late/shift boundaries. |

Also examined and **not** defects: `load_dotenv()` default (`override=False`, real env wins — correct); `department` exact match (contract says case-sensitive — correct); `list_attendance` total via filtered set (logic right, only slow); `PunchInIn.status` default `PRESENT` (correct); `history: []` initial value (correct).
